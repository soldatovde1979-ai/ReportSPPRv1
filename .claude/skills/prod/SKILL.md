# prod — выкладка в продуктив · версия 1.0 · 05.10.2026

**Продуктив = ветка `main` на GitHub** (my-FT Р-10, ноутбук с 5.2). Ноутбук открывается в Colab прямо с GitHub, модуль и шаблон ячейка 1 скачивает с GitHub при каждом прогоне. Копировать файлы на Google Диск не нужно: на Диске (`MyDrive/PROJECTs/ReportSPPRv1`, синхронизируется с ПК пользователя) лежат данные (история недель, кэш ИИ, результаты) и запасные копии модуля и шаблона — их ноутбук берёт, только когда GitHub недоступен, и предупреждает.

«Положить в продуктив» = убедиться, что `main` годен, и сказать пользователю, чем запускать.

## Шаги

1. **Всё в `main`.** `git status` чистый, `git fetch origin main`, `HEAD` = `origin/main`. Есть незапушенные коммиты релиза — стенд (шаг 2), потом `git push origin main`.
2. **Стенд.** `python3 examples/selftest_v5/run.py` → «ИТОГ: ОК». Без него — стоп, в продуктив не идёт.
3. **GitHub Actions.** Последний запуск workflow `selftest` на `main` (инструмент `mcp__github__actions_list`, `list_workflow_runs`) — `success`, и его `head_sha` — последний коммит с правкой файлов релиза (`git log -1 -- RepSSPR_v*.ipynb src/report_v5.py template_v5.html examples/`). Красный или ещё идёт — стоп, ждать или чинить.
4. **Версии.** Ноутбук `RepSSPR_v<М>.<м>.ipynb` — последний в корне; мажоры ноутбука, `VERSION` модуля и `TEMPLATE_VERSION` шаблона совпадают (стенд это проверяет — шаг 2).
5. **Диск — только просмотр** (Google Drive: `search_files` по папке `ReportSPPRv1`, id `18iI8F_qp8zkoFwHWocL1I1e18M9Wpa7j`). Ищем копии `report_v*.py` вне `src/` — их ноутбук возьмёт первыми, если GitHub недоступен: перечислить и с согласия пользователя убрать в корзину (`trash_file`). Файлы на Диск **не загружать**: инструмент только создаёт новый файл по тексту из запроса — для 225 КБ модуля это перепечатка без сверки содержимого. Запасные копии обновляются сами, когда пользователь делает `git pull` на ПК.
6. **Отчёт пользователю:**
   - коммит `main` и версии: ноутбук, модуль, шаблон;
   - стенд и GitHub Actions — итог;
   - ссылка на ноутбук: `https://colab.research.google.com/github/soldatovde1979-ai/ReportSPPRv1/blob/main/RepSSPR_v<М>.<м>.ipynb`;
   - после запуска ячейки 1 сверить строку `🧩 Модуль report_v5.py <версия> (GitHub)`; если `(запасная копия)` — GitHub недоступен, версия может быть старой;
   - GitHub отдаёт свежий файл с задержкой до 5 минут после push — если версия старая, перезапустить ячейку 1 позже;
   - напоминание: `git pull origin main` на ПК — обновит запасные копии на Диске.

## Чего не делать

- Не выкладывать при красном стенде или красном GitHub Actions.
- Не загружать и не перезаписывать файлы релиза на Диске через подключение.
- Не удалять на Диске ничего, кроме копий модуля и шаблона вне их мест, и то — с согласия пользователя.
