### 1.5 Lifecycle вычисляемых параметров (v4)

1. `WEEK_START` = понедельник недели, в которую попал **максимальный** `done_dt` среди решённых; `WEEK_END` = воскресенье; `WEEK_END_EXCL` = следующий понедельник 00:00. ⚠️ Одно решение, датированное следующим понедельником, переключит весь отчёт на новую, почти пустую неделю — граница определяется данными, а не параметром.
2. `max_year`, `max_week` — ISO-год и ISO-неделя `WEEK_START`; входят в заголовок и имя файла.
3. `REPORT_DATE` — `now()` на момент прогона, **не** момент выгрузки. Возраст открытых сдвигается при повторном прогоне той же выгрузки в другой день.
4. `TEMPLATE_PATH` — ищется: `CACHE_DIR` → при неудаче Диск `/content/drive/MyDrive/REPORTS/SPPR` (`os.walk`) → принудительный перемонт Диска и повтор. Если точного `TEMPLATE_FILE` нет — берётся самый свежий по `mtime` `template*.html` с сообщением в консоль. ⚠️ Проверки мажора шаблона нет.
5. История недель: сначала `CACHE_DIR/history.json`; если текущей недели там нет и `DRIVE_MODE != never` — дочитываются `HISTORY_DIR/week_*.json` (раздел 7).

### 2.2 Значения `st` и их роль в коде

| Группа в коде | Значения `st` (факт по дампу 22.09, 330 строк) |
|---|---|

| Отклонённые (`REJECTED_STATUS`) | Отклонено — 17 |
| Открытые — рабочие (`WORKFLOW_STATUSES`) | Уточнение — 61; Планирование разработки — 33; Анализ — 21; Ожидает анализа — 15; Внутреннее тестирование — 2; Разработка — 1; Релиз установлен — 1 |

## 3. Контракт LLM — батч-разметка решённых обращений (v4, ячейка 3)

### 3.1 Вход (одна строка пачки)

```
ID: {id} | Инициатор: {cli} | Аналитик: {anl}
Тема: {sec}
Тип (как указан): {type}
Описание: {desc[:1500]}
Решение: {sol[:1500]}
----------------------------------------
```

Пачка предваряется строкой `Оцени следующий пакет обращений:`. Системная инструкция `SYSTEM_INSTRUCTION` — f-строка (подставляется `KNOWN_TYPES`), разделы 0–7: лимиты длины, кластеризация, суть, рекомендация, критерии грейда, проверка типа, тон, сложность, альтернативное мнение, критичность, планшет.

### 3.2 Ответ: `BatchResponse{results: [TicketResult]}`

| Поле | Тип | Правило из промпта |
|---|---|---|
| `id` | str | Идентификатор из входа |
| `topic_cluster` | str ≤ 60 | Отглагольное существительное + объект; без «в 1С», «в системе»; запрет абстракций |
| `issue_summary` | str ≤ 90 | Суть одной строкой своими словами |
| `recommendation` | str ≤ 120 | Одно проверяемое действие против повтора |
| `suggested_type` | str ∈ `KNOWN_TYPES` | Тип по существу; **решение важнее формулировки** |
| `type_argument` | str ≤ 120 | Пусто, если тип совпал; иначе — на что опирались |
| `tone_deviation_score` | int 0–3 | 0 деловой … 3 оскорбления; исключения — обязательный 0 |
| `is_emotional` | bool | `tone_deviation_score > 0` |
| `emotion_argument` | str ≤ 120 | Обоснование тона |
| `complexity` | int 1–5 | 1 кнопка … 5 перерасчёт регистров |
| `initial_grade` | str | Исходная оценка |
| `final_grade` | str ∈ ПЛОХО / ХОРОШО / ОТЛИЧНО / Н/Д | `Н/Д` (v4.1) — разметка не удалась или оценки нет; в рейтинг и списки «Плохо/Лучшие» не входит. По умолчанию при успешной разметке ХОРОШО; ОТЛИЧНО — только доказанная превентивность, «не более каждому пятому» |
| `grade_argument` | str ≤ 250 | Аргументация грейда |
| `is_alternative` | bool | Формально закрыто, по существу не решено |
| `is_critical_incident` | bool | Заблокирован процесс / отгрузки / зарплата / > 5 пользователей |
| `planshet` | bool | Только слово «планшет» и его формы |
| `planshet_argument` | str | Цитата со словом «планшет» или пусто |

Транспорт: Gemini — `response_schema=BatchResponse`, `response_mime_type=application/json`, `temperature=0.1`, `max_output_tokens=8192`. DeepSeek — `response_format={"type":"json_object"}`, JSON Schema дописывается текстом в системный промпт, `temperature=0.1`, `max_tokens=8192`; принимается `{"results":[...]}` или голый список.

### 3.3 Повторы и заглушки

1. Исключение вызова → до 3 попыток на пачку, задержка ×2; после 3-й — пачка на повтор.
2. `JSONDecodeError` (обрыв ответа) → без повтора того же размера, пачка сразу на повтор.
3. Строки, которых нет в ответе, → на повтор.
4. Повтор = новый проход с пачкой вдвое меньше (`15 → 7 → 3 → 1`), всего не более 6 проходов.
5. Что не разметилось и по одной строке → `_fallback_rows`:

```json
{
  "id": "<из строки>", "topic_cluster": "<sec или 'Без темы'>", "issue_summary": "<sec или 'Нет данных'>",
  "recommendation": "", "suggested_type": "<type из выгрузки>", "type_argument": "",
  "tone_deviation_score": 0, "is_emotional": false, "emotion_argument": "",
  "complexity": 1, "initial_grade": "Н/Д", "final_grade": "Н/Д",
  "grade_argument": "Ошибка вызова API (<provider>): ответ модели не разобран",
  "is_alternative": false, "is_critical_incident": false, "planshet": false, "planshet_argument": ""
}
```

⚠️ Заглушка ставит `ХОРОШО` — пропуск разметки неотличим от нормальной оценки в рейтинге и распределении.

### 3.4 Нормализация после слияния (ячейка 5)

- `df_final = merge(df, df_ai, on='id', how='left')`; оба `id` — строки, дубли ответа схлопываются (`keep='first'`).
- `final_grade`: `NaN → 'Н/Д'` (v4.1; в v4.0 было `'ХОРОШО'`), upper/strip. `complexity`: `NaN → 1`; `tone_deviation_score`: `NaN → 0`.
- `is_critical_incident`, `is_alternative`, `planshet`: словарь `_BOOL_MAP`, всё прочее → `False`.
- `planshet` дополнительно обнуляется, если в `sec + desc + sol` нет подстроки «планшет».
- `issue_summary` пустой → `topic_cluster`; новые текстовые поля `NaN → ''`.
- `df_clean = df_final.fillna('')`.

### 3.1 Кэш разметки (v4.1, my-FT Т-63)

Файл `markup_cache.json`: `{ "<id>": { "key": "<sha1>", "row": { …16 полей ответа ИИ… } } }`.

- `key` — sha1 от текстов, которые видит модель (`cli`, `anl`, `sec`, `type`, `desc` и `sol` до `PROMPT_TEXT_LIMIT`), от `SYSTEM_INSTRUCTION` и от `BATCH_MODEL`. Правка решения, промпта или смена модели меняет ключ — обращение размечается заново.
- Сбойные заглушки (`Н/Д`) в кэш не пишутся.
- Хранилище: `CACHE_DIR/markup_cache.json` (всегда); при `DRIVE_MODE = always` ещё `HISTORY_DIR/markup_cache.json`. Файл можно скачать из панели Colab и приложить к следующему запуску — при `USE_FILE_PICKER` имя, содержащее `markup_cache`, принимается как кэш.
- Без Диска и без приложенного файла кэш живёт только в текущей сессии Colab.

## 4. Контракт LLM — группировка тем (v4, ячейка 4)

**Вход:** все уникальные `topic_cluster` недели, пронумерованные с 1; кавычки заменены на `'`, `\` на `/`, переводы строк — на пробел. Если уникальных ≤ `TOPIC_GROUPS_MIN` — группировка пропускается, `topic_group = topic_cluster`.

**Ответ:**

```json
{"groups": [{"name": "Не создаётся проект ДС при действующем ДС", "items": [1, 5, 12]}]}
```

**Обработка:**

| Ситуация | Поведение v4.0 |
|---|---|
| Номер вне диапазона / не число | отбрасывается |
| Номер строкой `"3"` | приводится к `int` |
| Тема в двух группах | ⚠️ побеждает **последняя** группа (`topic_to_group_map[t] = …` в цикле); прежняя документация утверждала «остаётся в первой» |
| Тема не попала ни в одну группу | ⚠️ группой становится сама формулировка (не «Прочее», как утверждала прежняя документация) |
| Название по стоп-листу, с « и », с запятой, из одного слова | второй проход `refine_group_names` → `{"names": ["…"]}`; неудачное новое имя не применяется |
| Ответ не парсится | до 3 попыток, затем `topic_group = topic_cluster` |

Модель: `BATCH_MODEL`, `temperature=0.1`, `max_tokens=8192`, JSON-режим.
⚠️ Токены группировки не считаются: переменная `group_tokens` в v4.0 не создаётся, в лог и на слайд уходит 0.
🔎 В отчёте W38 — 122 группы на 165 обращений при ориентире 8–15: большая часть тем осталась без группы. Причину по отчёту не установить — нужен вывод консоли прогона.

## 10. Табличные части обращения (необязательные)

Дополнительные данные по обращению приходят **внутри объекта обращения** отдельными полями-массивами (Т-54/Т-55 в `docs/my-FT.md`). Каждая часть — своё имя и свои колонки; строка части — массив значений в порядке колонок ниже. Постановка на 1С — `src/vygruzka-1c.md`, п. 2.4.

| Поле | Колонки строки | Типы | Смысл |
|---|---|---|---|
| `tab_trud` | исполнитель, часы | str, number | Трудозатраты обращения по исполнителям из `ЧасыФактПоКарточкам`. Сумма часов = `AmountTrud` |
| `tab_status` | дата, кто сменил, регистр, статус | `yyyy-MM-ddTHH:mm:ss`, str, «карточка» / «требование», str | Все смены статусов карточки и требования, по возрастанию даты |

Правила чтения (ноутбук v5, генератор макета):

1. **Нет поля, `null` или `[]` — «нет данных».** Не ошибка; блоки отчёта на этой части скрываются или пишут «нет данных». Части добавляются в 1С по одной.
2. Строка с другим числом колонок или нечитаемой датой отбрасывается, счётчик — в консоль и в паспорт данных.
3. Проверка сходимости: для каждого обращения с `tab_trud` сумма часов равна `AmountTrud` (допуск 0,05 ч); расхождения — в паспорт данных.
4. Держатель по статусу для `tab_status`: «Уточнение» — пользователь; «Новое», «Ожидает анализа», «Анализ», «Уточнение предоставлено», «Возврат на доработку», «Передано в работу» — поддержка; от «Планирование разработки» до «Проверка релиза» — разработка; «Отработано…», «Закрыто», «Отклонено» — время не считается.
5. Новая часть — новая строка этой таблицы и одна строка описания колонок в коде; существующие части не меняются.

Ноутбук v4.0 читает выгрузку через `pd.read_json` и обращается только к своим полям — табличные части ему не мешают (проверено по коду 30.09).

Демо: `examples/sppr_dump_20260929_180748_842rec_demo_tab.json` — копия выгрузки 29.09 с **выдуманными** частями (генератор `examples/make_demo_tab.py`); в её строках нет реальных данных о трудозатратах по исполнителям и истории статусов.

## 11. Контракты ИИ v5 (`RepSSPR_v5.1`, ячейки 2–6)

Эталон всех схем — `examples/mockup_v2_ai.json` (разметка для макета; ею же отвечает подставная модель при самопроверке).

### 11.0 Общие правила

- Все ответы модели — JSON. Вызов один на все этапы: `ai_call` (Gemini — `response_mime_type: application/json`; DeepSeek без рассуждения — `response_format: json_object`, `temperature 0.1`, `max_tokens 8192` для разметки; модель с рассуждением — JSON по инструкции в промпте, без `temperature` и `response_format`). Пустой ответ или нет `choices` — ошибка вызова.
- `ask_json`: до 3 попыток; ответ, не прошедший проверку кода, переспрашивается с перечнем ошибок («путь: ошибка»); после последней попытки остаются только годные строки (`report_v5.sanitize`); годный ответ кэшируется. Пауза перед повтором (2 с, ×2) — вне слота параллельности (`MAX_CONCURRENCY = 4`).
- Номера обращений `\d{2}-\d{8}` во всех строках — только из выгрузки; ключи `{метрика}` — только из каталога (11.4). Текст ИИ в отчёте экранируется, цифры подставляет код.
- Первая строка системного промпта каждого этапа — «ЗАДАЧА: …»: по ней подставная модель стенда самопроверки (`examples/selftest_v5/stubs/fake_model.py`) узнаёт этап. Новый этап или новая первая строка — добавить ответ и в подставную модель.

### 11.1 Разметка решённых за период — `tickets[]` (ячейка 3)

Вход — строка пачки:

```
ID: {id} | Инициатор: {cli} | Аналитик: {anl}
Раздел: {sec} | Тип (как указан): {type}
Зарегистрировано: {reg} | Решено: {done} | Срок: {h} раб. ч (8 ч в дне) | Трудозатраты: {AmountTrud} ч
Описание: {desc[:1500]}
Решение: {sol[:1500]}
----------------------------------------
```

Ответ — `{"results": [{…}]}`:

| Поле | Значение | Правило |
|---|---|---|
| `id` | str | Номер из входа |
| `g` | str ≤ 60 | Тема: отглагольное существительное + объект; после ячейки 4 — **группа**, тема — в `tc` |
| `s` | str ≤ 90 | Суть своими словами |
| `st` | `I` `D` `K` `P` `DB` `SVC` | Тип по сути: инцидент, правка данных, консультация, права, дубль, служебная карточка. Решение важнее формулировки |
| `ta` | str ≤ 120 | Аргумент типа; пусто, если совпал с указанным |
| `gr` | `О` `Х` `П`, для `SVC` — `—` | Оценка: по умолчанию «Х», «П» — при любом признаке, «О» — только доказанная превентивность |
| `ga` | str ≤ 250 | Аргумент оценки |
| `rec` | str ≤ 120 | Одно проверяемое действие против повтора; пусто, если повтор невозможен |
| `rr` | `в` `с` `н` | Риск повтора |
| `tone` / `ea` | 0–3 / str ≤ 120 | Тон пользователя и его признак |
| `cx` | 1–5, для `SVC` — null | Сложность решения |
| `crit` | bool | Критичный инцидент |
| `ss` | bool | Пользователь мог сделать сам при праве или инструкции |
| `obj` / `why` / `wa` | str ≤ 50 / причина / str ≤ 150 | Для правок данных: что правят («Объект: что»), почему — одна из 8 причин `WHY_ACT` (нет прав у пользователя, ошибка пользователя, дефект системы, штатная правка, разрыв процесса, пробел НСИ, нет функционала, ошибка ввода НСИ), обоснование |

Нормализация (`norm_ticket`): `st` — верхний регистр; `gr` — латинские O/X/P и слова «ОТЛИЧНО/ХОРОШО/ПЛОХО» приводятся к кириллице; `why` — без учёта регистра к справочнику; `rr` по первой букве (по умолчанию «с»); `tone`, `cx` — к числу в диапазоне; длины обрезаются. Строка без годных `st`, `gr`, `g`, `s` — на повтор. Не вернувшиеся строки и обрыв JSON — новый проход пачкой вдвое меньше (15 → 7 → 3 → 1, до 6 проходов). Не размеченные и по одной — «Н/Д»: записи нет, обращение не входит в оценки, рейтинг и списки (Т-64), число — в паспорте данных.
Поле `pl` эталона (признак планшета) в v5 не запрашивается: причина по планшетам — отдельный этап 11.3.

### 11.2 Группы тем (ячейка 4)

Вход — нумерованные темы с примерами: `N. тема — суть: «…»; «…» (разделы; обращений K)`. Ответ — `{"groups": [{"name": "…", "items": [1, 5]}]}`. Проверка: номера в диапазоне; «почти ничего не объединено» (групп не меньше 90% тем при 20 темах и больше) — один повтор с замечанием, затем ответ принимается. Названия по стоп-листу v4 (свалки, «и», запятая, одно слово) — второй проход `{"names": [...]}`. Тема вне групп — сама себе группа; дубль номера — побеждает первая группа. Ответ кэшируется: повторный прогон той же выгрузки даёт тот же топ-7.

### 11.5 Разборы слайдов — `slides.s1…s11` (ячейка 6)

Модель с рассуждением; девять разборов параллельно, сводный `s1` — после них. Вход: каталог метрик; текст слайда — то, что видит читатель (`report_v5.slide_texts`: заголовки, подписи, таблицы строками, из графиков — подсказки); описание (≤ 400) и решение (≤ 500) обращений со слайда, до 60; для `s4` — список не-правок НСИ за 4 недели и открытых; для `s9` — ФИО аналитиков; для `s1` — выводы остальных разборов с подставленными цифрами.

Каждый разбор: `{"summary": "…", "items": [{"fact", "conc", "act", "who", "eff", "ids": [...]}]}` плюс:

| Слайд | Дополнительно | Ограничения проверки |
|---|---|---|
| `s1` | `decisions` [{`problem`, `fact`, `ids`, `act`, `who`, `eff`}] — 5 решений; `root_all` [{`cause`, `ids`, `act`, `who`}] | `prev` (статусы решений прошлой недели) с 5.1 не запрашивается и не показывается (В-21); в эталоне `mockup_v2_ai.json` поле осталось — модуль его не читает |
| `s3` | `root` [{`cause`, `ids`, `fix`, `kind`}]; `notsolved` [{`id`, `done`, `why`, `risk`}]; `fix_first` [{`name`, `ids`, `act`}] | `notsolved.id` — решённое за период; `risk` — высокий / средний / низкий |
| `s4` | `nsi_nonedit` [{`id`, `cls`, `note`}] | `id` — обращение раздела «Нормализация» |
| `s6` | `best` [{`id`, `why`, `kb`}] | `id` — размеченное решённое за период |
| `s9` | `fix` {ФИО полностью: что поправить}; `case_best`, `case_worst` {`id`, `why`} | ФИО — из выгрузки; `id` — размеченное решённое за период |

Нет разбора (сбой или негодный ответ после 3 попыток) — в отчёте нейтральная строка «Разбор ИИ недоступен…», отчёт строится дальше.

### 11.6 Кэш ИИ — `markup_cache_v5.json`

```json
{"tickets":  {"00-00034982": {"key": "<sha1 строки промпта, промпта этапа и модели>", "row": {"…": "разметка 11.1"}}},
 "open_old": {"00-00016433": {"key": "<sha1>", "row": {"id": "…", "ag": "…", "s": "…", "a": "…"}}},
 "calls":    {"<sha1 модели, системного и пользовательского промпта>": {"v": "<ответ>", "ts": 1759363200.0}}}
```

Разметка решённых и старых открытых — по id (меняется текст, промпт или модель — размечается заново); ответы целых вызовов (группы, критичные, планшеты, сигналы, разборы) — по хэшу промпта, хранятся 60 дней; `REUSE_AI = False` — ответы вызовов не берутся. Сбои и негодные ответы не кэшируются. Кэш v4 (`markup_cache.json`, без ключа `tickets`) не читается.

### 11.7 Журнал этапов

`RUN_LOG`: `{stage, model, calls, cached, tokens, tok_in, tok_out, sec, note}` на этап — в консоль, в паспорт данных («Расход ИИ по этапам») и в лист `Token` (ячейка 8): Batch — «Разметка решённых», Summary — «Разбор s…», Group — «Группы тем» (модель разметки), Incidents — открытые, планшеты, скрытые повторы.

## 12. Модуль `report_v5` и шаблон `template_v5.html`

### 12.1 Модуль `src/report_v5.py` 5.1

Один модуль вызывают ноутбук и сборка макета `examples/build_mockup_v2.py` (my-FT Р-6, В-18 = а).

| Функция | Что делает |
|---|---|
| `load(выгрузка, имя_файла, report_week, history, demo)` | Строки, отчётный период, выборки (решено, пришло, отклонено, открыто, старше 30 дней, планшеты, 4 недели), табличные части, склейка ФИО по `cli_id` / `anl_id` (Т-69), проверка покрытия 4 недель. Время среза — из имени файла (Т-65) |
| `attach_ai(R, разметка)` | Разметка ИИ к строкам (тип по сути, служебные карточки), все метрики `R.M` |

| `validate(R, часть, ответ, слайд)`, `sanitize`, `errors_text`, `quote_ok` | Проверка ответов ИИ (11.3, 11.5) и отбор годных строк |

### 12.2 Шаблон `template_v5.html` 5.0

Jinja2, `autoescape`. Первая строка — комментарий с `TEMPLATE_VERSION = "5.0"`: модуль сверяет мажор с `TEMPLATE_MAJOR` и останавливается с ошибкой при несовпадении. Шаблон — оболочка: стили, верхняя панель, меню, переключение слайдов, сворачивание длинных таблиц.

| Переменная | Что это |
|---|---|
| `title` | Заголовок вкладки: «Качество 1С-поддержки · Неделя N» (макет — «Макет v2 — …») |
| `banner` | Текст плашки над отчётом — только макет; в отчёте нет |
| `period` | «Неделя N · период · срез» в верхней панели |
| `rail` | HTML меню слайдов (фильтр `safe`) |
| `slides` | HTML 11 слайдов (фильтр `safe`): s1 Неделя · s11 Сроки и долгострой · s2 Очередь · s3 Инциденты · s4 Ручные правки и НСИ · s5 Повторы · s7 Планшеты · s6 Качество и классификация · s9 Аналитики · s8 Цена в часах · s10 Паспорт данных |

Смена набора переменных — мажор шаблона, модуля и ноутбука в одной выдаче.
