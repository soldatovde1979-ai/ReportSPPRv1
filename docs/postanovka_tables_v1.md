## З-2. Причёсывание описания и решения (Т-79, Т-80)

1. В модуле — функция `clean_text(t)`. Убирает:
   - приветствия в начале каждой строки (повторами подряд): «Коллеги», «Добрый день / вечер», «Доброе утро», «Здравствуйте», «Приветствую», «Привет», «Уважаем… <до трёх слов>», имя перед приветствием («Ольга, добрый день»);

2. Вызов — в `load()` для `desc` и `sol`: в `r["desc"]`, `r["sol"]` — причёсанный текст; исходный — в `r["desc_raw"]`, `r["sol_raw"]`. Причёсанное пустое — берётся исходный.
3. Причёсанный текст получают все потребители: таблицы отчёта и промпты ИИ в ноутбуке (они читают `r["desc"]`, `r["sol"]` — ноутбук не меняется).

## З-3. Ячейка «Обращение» (Т-78)

Функция `tk()` — в таблицах, где строка = одно обращение:

```
00-00034811                                   ← номер; ссылка, если есть url
рег 17.09 · 12 дн. · Иванова Е. В.             ← мелко: регистрация, дней (у решённых — «реш 30.09»), инициатор
Морденко П. А.                                ← ниже: аналитик
Проведение операций по незарегистрированному…  ← краткое описание; клик — раскрытие (З-4)
```

1. Краткое описание: `name` из выгрузки → нет — суть от ИИ (`ai.s`) → нет — первые 100 символов причёсанного описания. Длиннее 100 символов — обрезка с «…».
2. Инициатор — `short(cli)`, как у аналитика.
3. В колонках со списком номеров (`tks()`: Парето, первопричины, повторы) — компактно, как сейчас (номер, дата, аналитик), но с раскрытием по клику.

## З-4. Раскрытие описания и решения (Т-78)

1. Клик по краткому описанию (или по «▸» в компактном виде) — под строкой таблицы появляется строка на всю ширину таблицы: «Описание» (причёсанное) и «Решение» (если есть). Повторный клик — свернуть.
2. Текст — не длиннее 3000 символов, дальше «…». Переводы строк сохраняются.
3. Работает без сети и без внешних библиотек: текст — в разметке отчёта, раскрытие — скрипт в существующем блоке скрипта шаблона, стили — в шаблоне (`TEMPLATE_VERSION = "5.1"`).
4. Колонки «Описание» и «Решение» из таблиц убрать: «Самые дорогие решённые» (слайд «Цена»), «Открытые по планшетам», «Связи из 1С: главное — дочернее», «Служебные карточки в потоке обращений» (там, где колонка «Что это» подставляет описание при пустой сути ИИ — подставлять краткое описание из п. ## З-5. Срок у держателя по истории статусов (Т-81)

Только при наличии `tab_status` у обращения. Нет истории — как сейчас.

1. Срок у держателя: идём по событиям `tab_status` регистра «карточка» от последнего к первому, пока держатель статуса (`HOLDER_OF`, по умолчанию «Разработка») равен текущему держателю; дата самого раннего такого события — начало. `r["hold_days"] = (NOW − начало).days`.
2. Панели «Кто сейчас держит открытые обращения / инциденты / правки» (`holder_rows`):
   - цветные корзины ≤7 / 8–30 / 31–90 / >90 — по `hold_days`;
   - под числом: «у держателя: медиана N дн · всего M дн · K ч»;
   - сноска «Что это» — откуда сроки и что без истории используется возраст от регистрации.
3. Если `hold_days` есть не у всех обращений панели — у кого нет, берётся возраст от регистрации; в сноске — «по истории — X из Y».
4. Таблицы «старше 30 дней» не меняются.
