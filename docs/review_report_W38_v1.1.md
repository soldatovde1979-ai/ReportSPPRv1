## 3. Непонятность и оформление

1. **Названия без смысла и единиц.** «Решено за рабочий день» → «Решено в пределах рабочего дня: ≤ 8 раб. ч от регистрации до решения». «Медиана, ч» → «раб. ч = календарные / 3». «Долгострой (> 40 ч)» → «шли дольше рабочей недели».
2. **Нет выборки и периода.** На одном слайде смешаны неделя, срез открытых и вся выгрузка. В макете — метки: ▲ пришло за неделю, ▼ решено за неделю, ✕ отклонено, ● открыто на дату, ◆ вся выгрузка, ◇ история, ✦ разбор ИИ. Правило: цифры с разными метками не сравниваются и не складываются.
3. **Нет «зачем».** В макете у каждого блока серая сноска: что показывает и какое решение на нём принимается.
4. **Первый слайд перегружен и не отвечает на главный вопрос** «справились ли с потоком». Две карточки «медиана/среднее» с тремя цифрами каждая, два одноцветных графика по дням без типов, шесть плиток разной природы.
5. **Разборы ИИ — стены текста** в прокрутке под таблицами. Лучшее («разовые заплатки», «доработки на группу») спрятано пунктами 7–8 внутри блока «Инциденты закрытые».
6. **Подсветка «красным — группы с долей инцидентов > 50%»** на W38 ничего не подсвечивает: у всех 5 групп 0%, все они — правки данных. Полезнее показывать тип-лидер группы.
7. **Эмоциональный фон** — отдельный слайд на 1 обращение. При < 3 обращений — строка в приложении.

## 6. Структурированный ответ ИИ вместо текста

**Рекомендация — структура JSON, а не разбор текста.** Разбор свободного HTML хрупок: модель меняет заголовки и нумерацию от недели к неделе. Структурированный ответ уже работает в ячейке 3 (Gemini `response_schema`, DeepSeek `json_object`) — тот же приём переносится на разборы. Шаблон рендерит таблицы и карточки макросами.

Три правила против выдумок:
1. **Номера обращений проверяет код**: `ticket_ids` ⊆ множеству id во входе, остальное отбрасывается и считается в консоли.
2. **Цифры ИИ не пишет**, а ссылается на ключи метрик: `"fact": "{dev_open} открытых у разработки, медиана {dev_age_med} дн."` — код подставляет значения, неизвестный ключ → строка отбрасывается.
3. **Каждый раздел обязателен**: пустой список допустим только с полем `empty_reason`.

Схемы (⏳ предложение):

```json
{
  "decisions": [
    {"problem": "str ≤ 60", "fact": "str с {метриками}", "action": "str ≤ 120", "owner_role": "str ≤ 40"}
  ],
  "root_causes": [
    {"cause": "str ≤ 100", "ticket_ids": ["00-…"], "fix": "str ≤ 140",
     "fix_kind": "доработка | настройка | регламент | обучение"}
  ],
  "one_off_patches": [
    {"ticket_id": "00-…", "what_done": "str ≤ 80", "why_returns": "str ≤ 140", "risk": "высокий | средний | низкий"}
  ],
  "group_fixes": [
    {"title": "str ≤ 80", "closes_ids": ["00-…"], "effect": "str ≤ 120", "priority": "1..5"}
  ],
  "escalate_now": [
    {"ticket_id": "00-…", "reason": "str ≤ 120"}
  ],
  "empty_reason": {"one_off_patches": "str — если список пуст"}
}
```

Новые поля разметки обращения (ячейка 3, ⏳):

| Поле | Значения | Для чего |
|---|---|---|
| `data_object` | справочник: Контрагент, Договор/ДС, Протокол НМЦ, Сотрудник/подразделение, Пропуск/СКУД, Счёт/оплата, Заявка/закупка, Номенклатура, Документ ЭДО, Права/роль, Прочее | «Что правят» на слайде 4 вместо ключевых слов |

| `self_service` | bool | Мог ли пользователь сделать сам при наличии прав или инструкции |
| `cause_named` | bool | Названа ли причина в решении — основа доли «Плохо» и «заплаток» |
| `repeat_risk` | высокий / средний / низкий | Кандидаты в «Разовые заплатки» по всем типам, не только инцидентам |

## 8. Рейтинг аналитиков с оценками пользователей

Если у самых загруженных почти сплошные пятёрки, среднее балла людей не различает. Предлагаю:

1. **Доля оценок ниже 5** со сглаживанием по числу оценок: `(k + p₀·m) / (n + m)`, где `k` — оценки < 5, `n` — все оценки аналитика, `p₀` — доля по команде, `m ≈ 10`. У кого 3 оценки, тот не получит случайные 0% или 100%.
2. **Жалобы** — число оценок ≤ 3, каждая — ссылка на обращение.
3. **Отклик** — доля обращений с оценкой: низкий отклик = оценка непредставительна.
4. **Качество по ИИ** — доля «Плохо» и доля «Отлично» (доли, не суммы).
5. **Скорость** — медиана времени к медиане своего типа.
6. **Нагрузка** — Σ сложности, с трудочасами — сложность на час.
7. В рейтинг — от 5 решённых. Одного итогового балла не строить; если место всё же нужно — сортировка по качеству, затем по скорости.
