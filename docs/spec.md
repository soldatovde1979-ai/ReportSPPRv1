## 1. Обзор системы

Ноутбук Google Colab `RepSSPR_v5.0.ipynb` раз в неделю строит HTML-отчёт о работе службы «1С Корпоративная поддержка» — 11 слайдов в формате макета v2 (`examples/mockup_report_v2.html`). Вход — JSON-выгрузка обращений из 1С (`СформироватьJSONНаСервере`, см. `vygruzka-1c.md`): решённые и отклонённые за период (рабочий режим — 4 недели) плюс все открытые на момент выгрузки. Ноутбук размечает решённые за период и старые открытые обращения моделью (DeepSeek или Gemini), сводит темы в группы, получает от модели разбор каждого слайда в JSON, проверяет цифры и номера кодом и собирает отчёт. Расчёт и вёрстку делает модуль `report_v5.py` — тот же, что собирает макет: макет и боевой отчёт не расходятся (my-FT Р-6). История недель (поток по типам, решения руководителя) хранится в кэше сессии и на Google Диске; ответы модели кэшируются, повторный прогон той же выгрузки бесплатен.

> ⚠️ Расшифровка «СППР» пользователем явно не подтверждена (в `vygruzka-1c.md` — название базы-источника обращений).

## 2. Архитектура и стек

1. **Выгрузка 1С** — серверная функция BSL; даты `yyyy-MM-ddTHH:mm:ss`; статус из двух регистров; необязательные табличные части `tab_trud`, `tab_status`, поля `url`, `cli_id`, `anl_id` (постановки).
2. **Модуль `src/report_v5.py`** — чистый Python + Jinja2: загрузка и отчётный период, срок решения по рабочему календарю, выборки и метрики, каталог метрик для ИИ, проверка ответов ИИ, история v2, текст слайдов для промптов, вёрстка 11 слайдов (inline SVG, без внешних зависимостей).
3. **Шаблон `template_v5.html`** — оболочка страницы: стили, панель, меню, переключение слайдов. Мажор шаблона проверяет модуль.
4. **Ноутбук** — ввод-вывод Colab (окно загрузки, Диск, секреты), вызовы модели (`openai.AsyncOpenAI` для DeepSeek, `google.genai` для Gemini), кэш ИИ, журнал этапов, лог в Google Sheets по флагу.
5. **Макет** — `examples/build_mockup_v2.py`: тот же модуль + разметка `examples/mockup_v2_ai.json` → `examples/mockup_report_v2.html`.
6. **Среда** — ноутбук только Colab (`google.colab.files/userdata/drive/auth`); модуль и макет работают где угодно (Python 3.10+, Jinja2).

## 4. Ключевые алгоритмы и workflow (v5)

Порядок ячеек менять нельзя: они делят общие переменные (`R`, `AI_MARKUP`, `AI_CACHE`, `RUN_LOG`, `HISTORY`, клиенты ИИ).

### 4.1 Ячейка 1 — параметры, файлы, неделя

Клиент модели (ключ — только из секрета выбранного провайдера, Т-66) → Диск лениво → окно загрузки (выгрузка, шаблон, модуль, история, кэш ИИ) → модуль и шаблон по точному имени с проверкой мажора — **до** платных вызовов → история недель → `report_v5.load`: отбрасывается старая доска (Т-21), срок решения — 8 ч в рабочем дне без выходных и праздников (Т-67, Т-68), период — с понедельника недели максимальной даты решения или `REPORT_WEEK` (Т-12), срез открытых — момент выгрузки из имени файла (Т-65), первая линия (Т-10), НСИ (Т-11), служебные карточки, держатели открытых, планшеты, 4 недели.

### 4.2 Ячейка 2 — вызов ИИ

`ai_call` — один вход для всех этапов и обоих провайдеров; `ask_json` — проверка ответа кодом, повтор с перечнем ошибок, годные строки после последней попытки, кэш по хэшу промпта; `Stage` — журнал этапа (вызовы, кэш, токены, секунды). Подробно — `data.md`, 11.0, 11.6, 11.7.

### 4.3 Ячейка 3 — разметка решённых за период

Пачки по 15 параллельно (4 потока); кэш по id; строка с негодным типом или оценкой и не вернувшиеся строки — на повтор, обрыв JSON — пачка пополам; не размеченные — «Н/Д» (Т-63, Т-64). Схема — `data.md`, 11.1.

### 4.4 Ячейка 4 — группы тем

Темы с примерами сути → группы по объекту и проблеме; одиночные группы допустимы, свалки и группы-модули запрещены; «почти без объединений» — один повтор; плохие названия — второй проход. Топ-7 точечных проблем (Т-44) считается по группам.

### 4.5 Ячейка 5 — открытые, планшеты, повторы

Параллельно: действие по каждому открытому старше 30 дней (Т-20, Т-22), критичные открытые инциденты (Т-45), причина по каждому обращению про планшеты (Т-41), скрытые повторы с дословной цитатой (Т-42). Затем `attach_ai` — все метрики.

### 4.6 Ячейка 6 — разборы слайдов

Девять разборов параллельно, сводный разбор недели (s1: 5 решений руководителя, первопричины, контроль решений прошлой недели) — после них, по их выводам. Модель видит текст слайда, каталог метрик и первоисточники; цифры — ключами, номера — из выгрузки; ошибка — повторный запрос (Т-7, Т-32, Т-33, Т-43, Т-50, Т-52).

### 4.7 Ячейка 7 — история, отчёт

История v2 за недели, которые выгрузка покрывает целиком, с решениями руководителя (Т-52, В-15); Диск — только изменившиеся недели. `report_v5.render` → `Отчет по качеству W{N} ({первая дата решения}).html` (при совпадении имени — `_vK`), скачивание; без Диска скачиваются ещё `history.json` и кэш ИИ.

### 4.8 Ячейка 8 — лог в Google Sheets

Только при `IS_DEBUG == 1`, как в v4.2; токены — из журнала этапов (`data.md`, 11.7). Сбой записи не мешает отчёту — ячейка идёт после него.

## 5. Правила для ИИ-ассистента при доработке

1. Перед правкой обязан прочитать `spec.md` и `data.md`; имена полей выгрузки, ответа ИИ и переменных шаблона — только из `data.md`.
2. Порядок ячеек не менять; перенос кода между ячейками — только с проверкой общих переменных.
3. Каждую точечную правку в ноутбуке сопровождать комментарием проекта:
   ```python
   # ЧТО ИЗМЕНЕНО: <что>
   # ПОЧЕМУ: <зачем>
   ```
4. Результат правок возвращать **блоками, которые изменены**, даже если исходник передан одним файлом; к каждому блоку — что и зачем изменено [чат 29.09].
5. Версии: ноутбук `RepSSPR_v<МАЖОР>.<МИНОР>.ipynb`, модуль `src/report_v<МАЖОР>.py` (минор — `VERSION` внутри), шаблон `template_v<МАЖОР>.html` (минор — `TEMPLATE_VERSION` в первой строке); мажоры совпадают и проверяются кодом. Смена переменных шаблона или контракта модуля — мажор всех трёх в одной выдаче и правка `MODULE_FILE` / `TEMPLATE_FILE` в ячейке 1.
9. Расчёт и вёрстка — только в модуле `src/report_v5.py`; макет собирается тем же модулем (`examples/build_mockup_v2.py`). После правки модуля — пересобрать макет и сверить с прежним: отличаться должно только задуманное.
6. Секреты — только `userdata.get(...)`, без литералов и fallback-строк.
7. Каждый элемент отчёта (плитка, график, таблица, блок ИИ) обязан иметь говорящее название, явную подпись периода и выборки (решённые / пришедшие / открытые / вся выгрузка) и серую мелкую сноску — какую пользу даёт или какую проблему показывает блок [чат 29.09].
8. Known Issues (разд. 7) попутно не чинить без запроса, но и не повторять в новом коде.
