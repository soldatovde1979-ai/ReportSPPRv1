## 1. Обзор системы

Ноутбук Google Colab `RepSSPR_v4.0.ipynb` раз в неделю строит HTML-презентацию о работе службы «1С Корпоративная поддержка». Вход — JSON-выгрузка обращений из 1С (`СформироватьJSONНаСервере`, см. `vygruzka-1c.md`): решённые и отклонённые за период плюс **все открытые** на момент выгрузки. Ноутбук режет данные по отчётной неделе, считает SLA, размечает каждое решённое обращение через LLM (Gemini или DeepSeek), группирует темы вторым проходом, получает от «аналитической» модели 6 текстовых разборов и рендерит самодостаточный HTML (20 слайдов, inline SVG, без внешних зависимостей). История недель хранится в кэше сессии и на Google Диске, лог запусков в Google Sheets — по флагу.

> ⚠️ Расшифровка «СППР» пользователем явно не подтверждена (в `vygruzka-1c.md` — название базы-источника обращений).

## 2. Архитектура и стек

1. **Выгрузка 1С** — серверная функция BSL; даты `yyyy-MM-ddTHH:mm:ss`; статус из двух регистров (`ИсторияСтатусовКарточек`, `ИсторияИзмененияТребований`).
2. **Приём и срез недели** — `pandas`, ячейка 1.
3. **SLA** — `pandas`/`numpy`, ячейка 2: календарные часы / 3.
4. **Разметка обращений** — `asyncio` + `google.genai` (async) или `openai.AsyncOpenAI` (DeepSeek), Pydantic-схема `TicketResult`, адаптивный размер пачки.
5. **Группировка тем** — один вызов `BATCH_MODEL` по всему списку формулировок, ответ номерами.
6. **Агрегация и разрезы** — `pandas` (`groupby`, `crosstab`), ячейки 5 и 5А.
7. **Текстовые разборы** — 6 вызовов `SUMMARY_MODEL` (Root-Cause + 5 комментариев), ответ — свободный HTML.
8. **История** — `history.json` в `/content/sppr_cache` + `week_*.json` на Диске; монтирование Диска ленивое (`ensure_drive`).
9. **Лог** — `gspread`, листы `Logs` и `Token`, только при `IS_DEBUG == 1`.
10. **Рендер** — `jinja2.Template`, шаблон `template_v4.html` из кэша или с Диска.
11. **Среда** — только Colab: `google.colab.files/userdata/drive/auth`. Вне Colab не запускается без переписывания ввода-вывода.

## 4. Ключевые алгоритмы и workflow

Порядок ячеек менять нельзя: они делят глобальные переменные (`df`, `df_all`, `df_open`, `df_final`, `df_clean`, `hist_map`, клиенты ИИ).

### 4.1 Ячейка 1 — параметры, клиенты, загрузка, срез недели

1. Клиенты: `client_gemini` (если есть ключ), `client_deepseek_async/sync` (ключ DeepSeek обязателен всегда).
2. `USE_FILE_PICKER=True`: окно загрузки; файлы раскладываются по расширению — `*.html` → `CACHE_DIR` (шаблон), `*history*.json` → `CACHE_DIR/history.json`, первый `*.json/*.csv` — выгрузка. Иначе — последний по `mtime` файл из `SOURCE_DIR_VARIANTS` (нужен Диск).
3. Парсинг: `reg_dt/cls_dt/res_dt`; `id/st/type/sec` → `str.strip()`; `done_dt = res_dt.fillna(cls_dt)`.
4. Наборы: `df_all` (всё), `_closed_pool` (решённые), `df_open` (не решённые и не отклонённые), `_rejected_pool`.
5. **Отчётная неделя**: понедельник–воскресенье, в которую попал максимальный `done_dt` решённых → `WEEK_START/WEEK_END/WEEK_END_EXCL`, `max_year/max_week`, `WEEK_LABEL`.
6. В неделю режутся: `df_closed` (по `done_dt`), `df_rejected` (по `cls_dt`). Счётчики `OUT_OF_WEEK_CLOSED`, `REJECTED_NO_DATE`, `DONE_TOTAL = решено + отклонено`.
7. `REPORT_DATE = now()`; `df = df_closed`; при `TEST_SAMPLE_SIZE > 0` — первые N строк.

### 4.2 Ячейка 2 — SLA

`dif_Hour = round(max(0, (done_dt − reg_dt)[ч] / 3), 1)`. Вычет 24 ч и `busday_count` удалены. При доле нулей > 20% — предупреждение о датах без времени. На дампе 22.09: медиана 7,8 ч, среднее 31,5 ч, нулей нет.

> ⚠️ Деление на 3 учитывает ночи, выходные и праздники: обращение, пришедшее в пятницу 17:00 и решённое в понедельник 9:00, получает 21,3 «рабочих часа».

### 4.3 Ячейка 3 — разметка решённых обращений

1. `SYSTEM_INSTRUCTION` (f-строка) + пачка строк `ID | Инициатор | Аналитик / Тема / Тип (как указан) / Описание[:1500] / Решение[:1500]`.
2. `call_ai_provider_batch` — Gemini со `response_schema=BatchResponse` или DeepSeek в JSON-режиме со схемой в тексте.
3. `process_chunk`: 3 попытки на исключения; обрыв JSON — сразу на повтор; строки, не вернувшиеся от модели, — на повтор.
4. `run_batching`: до 6 проходов, пачка делится пополам (`15 → 7 → 3 → 1`); неразмеченные по одной — `_fallback_rows` (грейд `ХОРОШО`).
5. `df_final = merge(df, df_ai, on='id', how='left')` со строковым `id` и схлопыванием дублей.

### 4.4 Ячейка 4 — группировка тем

Уникальные `topic_cluster` → нумерованный список → `{"groups":[{"name","items":[номера]}]}` → проверка названий по стоп-листу, « и », запятым и однословности → второй проход `refine_group_names` → `topic_group`. Неразложенная тема остаётся сама себе группой; при сбое — `topic_group = topic_cluster`. Подробно — `data.md`, разд. 4.

### 4.5 Ячейка 5 — нормализация, топы, история, Root-Cause

1. Нормализация ответа ИИ (`data.md`, 3.4), перепроверка `planshet` по тексту, `df_clean = fillna('')`.
2. `medHour` — медиана `dif_Hour`; `top_topics` — топ-5 групп с разделом-лидером (`«Договоры +2»`), долей инцидентов (≥ 50% — красная строка), модой грейда и тремя `issue_summary`.
3. Выборки: `longest_tickets` (10), `emo_tickets`, `crit_tickets`, `bad_tickets` (10), `exc_tickets` (10), `planshet_tickets`; честный `bad_count`.
4. История: кэш → при новой неделе дочитывание Диска → `w1_t/w1_m` предыдущей недели → `current_week_data` (`incidents` пока `None`).
5. Root-Cause: `summary_for_ai` → `SUMMARY_MODEL` → `ai_conclusions` (`<li>`).

### 4.6 Ячейка 5А — разрезы для слайдов и проверка сходимости

1. `type_tiles` — типы по **всей выгрузке** (330).
2. `daily_closed` (по `done_dt`) и `daily_reg` (по `reg_dt` всей выгрузки) — 7 точек пн–вс, пустые дни нулями.
3. `timeline_median/mean` — `reg→res`, `res→cls`, `reg→cls` в «рабочих часах».
4. `group_bars` — топ-10 групп тем + `group_rest`.
5. `week_stats` — 6 плиток (формулы и дефекты — `data.md`, 8.1).
6. `top_initiators_ext` — топ-5 инициаторов недели с группировкой по `issue_summary`.
7. `misclassified_rows` — решённые, где `suggested_type ≠ type` (регистр не важен).
8. Открытые: `open_old/open_new` по 30 дням; `cleanup_rows` — старше 30 дней и не в `WORKFLOW_STATUSES`; `age_bars4` — 4 корзины; `open_matrix_new` — блок × статус.
9. `type_matrix` — блок × тип по решённым за неделю.
10. Инциденты — по **всей выгрузке**: `incidents_closed` (решённые), `incidents_open` (всё прочее, включая отклонённые), `crit_incident_rows` (без фильтра недели), `inc_age_bars`, `timeline_points` (только зарегистрированные на неделе, x = 40…960).
11. История: `current_week_data['incidents'] = incident_total` → `save_history` (кэш всегда; Диск — если неделя новая или цифры изменились).
12. Планшеты — поиск подстроки «планшет» по `sec + desc + sol` **всей выгрузки**.
13. `validation_rows` — 7 проверок сходимости (строк = неделя + вне недели + открытые; решённые; отклонённые; покрытие оценками ИИ; инциденты; открытые по возрасту; сумма по типам).

### 4.7 Ячейка 5Б — комментарии ИИ к слайдам

5 последовательных вызовов `ask_analyst()` → `ai_comments` с ключами `inc_closed`, `inc_open`, `inc_total`, `initiators`, `types`; токены копятся в `incidents_tokens`; `incidents_analysis` — алиас `inc_total`. Входы и дефекты входов — `data.md`, разд. 5.

### 4.8 Ячейка 6 — лог в Google Sheets

Только при `IS_DEBUG == 1`: авторизация Colab → `gc.open('Logs')` → строка в `Logs` (`TEST`/`SUCCESS`) и в `Token` (12 колонок, шапка обновляется сама).

### 4.9 Ячейка 7 — рендер и экспорт

1. `_pick()`: точное имя `TEMPLATE_FILE`, иначе самый свежий `template*.html`; порядок поиска — кэш, Диск, Диск после перемонтирования; найденный на Диске шаблон копируется в кэш.
2. Досчёт: `midHour`, эмоции, `alt_tickets`, `exc_tickets` (перезаписывается на `head(5)`), `hardest/easiest_tickets`, рейтинг аналитиков, номинации, данные графика динамики (последние 6 недель).
3. Рейтинг: `score = (ОТЛИЧНО×3 + ХОРОШО×1 − ПЛОХО×3) × средняя complexity`, топ-10 по убыванию.
4. `template.render(...)` — 88 переменных (`data.md`, разд. 8) → `TARGET_DIR/Отчет по качеству W{N} ({дата}).html` с суффиксом `_vK` при коллизии → `files.download()`; при неподключённом Диске — ещё и `history.json`.

## 5. Правила для ИИ-ассистента при доработке

1. Перед правкой обязан прочитать `spec.md` и `data.md`; имена полей выгрузки, ответа ИИ и переменных шаблона — только из `data.md`.
2. Порядок ячеек не менять; перенос кода между ячейками — только с проверкой общих переменных.
3. Каждую точечную правку в ноутбуке сопровождать комментарием проекта:
   ```python
   # ЧТО ИЗМЕНЕНО: <что>
   # ПОЧЕМУ: <зачем>
   ```
4. Результат правок возвращать **блоками, которые изменены**, даже если исходник передан одним файлом; к каждому блоку — что и зачем изменено [чат 29.09].
5. Версии: ноутбук `RepSSPR_v<МАЖОР>.<МИНОР>.ipynb`, шаблон `template_v<МАЖОР>.html`; мажор ноутбука = версия шаблона. Смена набора переменных шаблона — МАЖОР обоих в одной выдаче и правка `TEMPLATE_FILE` в ячейке 1.
6. Секреты — только `userdata.get(...)`, без литералов и fallback-строк.
7. Каждый элемент отчёта (плитка, график, таблица, блок ИИ) обязан иметь говорящее название, явную подпись периода и выборки (решённые / пришедшие / открытые / вся выгрузка) и серую мелкую сноску — какую пользу даёт или какую проблему показывает блок [чат 29.09].
8. Known Issues (разд. 7) попутно не чинить без запроса, но и не повторять в новом коде.
