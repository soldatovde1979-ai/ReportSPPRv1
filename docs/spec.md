## 1. Обзор системы

Ноутбук `RepSSPR.ipynb` — в Google Colab или локально на ПК (my-FT Т-99) — раз в неделю строит HTML-отчёт о работе службы «1С Корпоративная поддержка» — 11 слайдов в формате макета v2 (`examples/mockup_report_v2.html`). Вход — JSON-выгрузка обращений из 1С (`СформироватьJSONНаСервере`, см. `vygruzka-1c.md`): решённые и отклонённые за период (рабочий режим — 4 недели) плюс все открытые на момент выгрузки. Ноутбук размечает решённые за период и старые открытые обращения моделью (OpenCoder, DeepSeek или Gemini; провайдер — `AI_PROVIDER`, по умолчанию `auto`: в Colab — DeepSeek, локально — OpenCoder), сводит темы в группы, получает от модели разбор каждого слайда в JSON, проверяет цифры и номера кодом и собирает отчёт. Расчёт и вёрстку делает модуль `report_v6.py` — тот же, что собирает макет: макет и боевой отчёт не расходятся (my-FT Р-6). История недель (поток по типам, решения руководителя) хранится на Google Диске (Colab) или в `result/history/` папки проекта (локально); ответы модели кэшируются, повторный прогон той же выгрузки бесплатен.

> ⚠️ Расшифровка «СППР» пользователем явно не подтверждена (в `vygruzka-1c.md` — название базы-источника обращений).

## 2. Архитектура и стек

1. **Выгрузка 1С** — серверная функция BSL; даты `yyyy-MM-ddTHH:mm:ss`; статус из двух регистров; необязательные табличные части `tab_trud`, `tab_status`, поля `url`, `cli_id`, `anl_id` (постановки).
2. **Модуль `src/report_v6.py`** — чистый Python + Jinja2: загрузка и отчётный период, срок решения по рабочему календарю, выборки и метрики, каталог метрик для ИИ, проверка ответов ИИ, история v2, текст слайдов для промптов, вёрстка 11 слайдов (inline SVG, без внешних зависимостей).
3. **Шаблон `template_v6.html`** — оболочка страницы: стили, панель, меню, переключение слайдов. Мажор шаблона проверяет модуль.
4. **Ноутбук** — ввод-вывод: в Colab — окно загрузки, Диск, секреты Colab; локально — папка проекта, переменные окружения и `.env`; вызовы модели (`openai.AsyncOpenAI` для DeepSeek и OpenCoder, `google.genai` для Gemini), кэш ИИ, журнал этапов, лог по флагу (CSV).
5. **Макет** — `examples/build_mockup_v2.py`: тот же модуль + разметка `examples/mockup_v2_ai.json` → `examples/mockup_report_v2.html`.
6. **Среда** — ноутбук: Google Colab (есть `google.colab`) или локальный Jupyter (`run_local.bat`, библиотеки — `requirements.txt`); режим определяется сам. Модуль и макет работают где угодно (Python 3.10+, Jinja2).

### 4.1 Ячейка 1 — параметры, файлы, неделя

Среда (`RUN_ENV`: colab / local, по наличию `google.colab`; локально пути — от папки ноутбука, Т-99) → провайдер (`auto`: Colab — DeepSeek, локально — OpenCoder) → клиент модели (ключ — `get_secret` выбранного провайдера, Т-66, В-25; opencoder — плейсхолдер `local`, прокси проверяется соединением до платных этапов) → Диск лениво (локально — папка проекта) → окно загрузки (выгрузка, шаблон, модуль, история, кэш ИИ) → модуль и шаблон по имени из мажора ноутбука: окно загрузки → GitHub (`CODE_SOURCE`, `GITHUB_API`, с 5.2) → кэш сессии и Диск с предупреждением; локально — сразу папка проекта; проверка мажора — **до** платных вызовов → история недель → `rv.load` (модуль): отбрасывается старая доска (Т-21), срок решения — 8 ч в рабочем дне без выходных и праздников (Т-67, Т-68), период — с понедельника недели максимальной даты решения или `REPORT_WEEK` (Т-12), срез открытых — момент выгрузки из имени файла (Т-65), первая линия (Т-10), НСИ (Т-11), служебные карточки, держатели открытых, планшеты, 4 недели. С 5.3 (З-2): `desc`/`sol` причёсываются `clean_text` (исходник — `desc_raw`/`sol_raw`), читается `name`; у открытых считается `hold_days` по `tab_status` (З-5) — причёсанный текст получают и промпты ИИ, ноутбук не меняется.

### 4.2 Ячейка 2 — вызов ИИ

`ai_call` — один вход для всех этапов и обоих провайдеров; `ask_json` — проверка ответа кодом, повтор с перечнем ошибок, годные строки после последней попытки, кэш по хэшу промпта; `Stage` — журнал этапа (вызовы, кэш, токены, секунды). Подробно — `data.md`, 11.0, 11.6, 11.7.

### 4.3 Ячейка 3 — разметка решённых за период

Пачки по 15 параллельно (4 потока); кэш по id; строка с негодным типом или оценкой и не вернувшиеся строки — на повтор, обрыв JSON — пачка пополам; не размеченные — «Н/Д» (Т-63, Т-64). Схема — `data.md`, 11.1.

### 4.4 Ячейка 4 — группы тем

Темы с примерами сути → группы по объекту и проблеме; одиночные группы допустимы, свалки и группы-модули запрещены; «почти без объединений» — один повтор; плохие названия — второй проход. Топ-7 точечных проблем (Т-44) считается по группам.

### 4.5 Ячейка 5 — открытые, планшеты, повторы

### 4.6 Ячейка 6 — разборы слайдов

### 4.7 Ячейка 7 — история, отчёт

## 5. Правила для ИИ-ассистента при доработке

1. Перед правкой обязан прочитать `spec.md` и `data.md`; имена полей выгрузки, ответа ИИ и переменных шаблона — только из `data.md`.
2. Порядок ячеек не менять; перенос кода между ячейками — только с проверкой общих переменных.
3. Каждую точечную правку в ноутбуке сопровождать комментарием проекта:
   ```python
   # ЧТО ИЗМЕНЕНО: <что>
   # ПОЧЕМУ: <зачем>
   ```
4. Результат правок возвращать **блоками, которые изменены**, даже если исходник передан одним файлом; к каждому блоку — что и зачем изменено [чат 29.09].
5. Версии (Р-12): ноутбук — постоянное имя `RepSSPR.ipynb`, версия `NOTEBOOK_VERSION` внутри; модуль `src/report_v<МАЖОР>.py` (`VERSION` внутри), шаблон `template_v<МАЖОР>.html` (`TEMPLATE_VERSION` в первой строке); мажоры совпадают и проверяются кодом. Имена модуля и шаблона вычисляются из мажора (ноутбук, стенд, сборщик макета, CI) — руками не вписываются. Смена переменных шаблона или контракта модуля — мажор всех трёх в одной выдаче: `git mv` модуля и шаблона, три версии, пересборка макета.
9. Расчёт и вёрстка — только в модуле `src/report_v6.py`; макет собирается тем же модулем (`examples/build_mockup_v2.py`). После правки модуля — пересобрать макет и сверить с прежним: отличаться должно только задуманное.
10. После правки модуля, ноутбука или шаблона — стенд `python3 examples/selftest/run.py`; без «ИТОГ: ОК» не коммитить. Задуманное изменение отчёта — пересобрать макет и закоммитить вместе с правкой, иначе сценарий «а» стенда покажет расхождение (my-FT Т-72).
6. Секреты — только `get_secret(...)` ячейки 1 (Colab — `userdata`, локально — окружение и `.env`), без литералов и fallback-строк.
7. Каждый элемент отчёта (плитка, график, таблица, блок ИИ) обязан иметь говорящее название, явную подпись периода и выборки (решённые / пришедшие / открытые / вся выгрузка) и серую мелкую сноску — какую пользу даёт или какую проблему показывает блок [чат 29.09].
8. Known Issues (разд. 7) попутно не чинить без запроса, но и не повторять в новом коде.
